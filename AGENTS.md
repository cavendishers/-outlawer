# AGENTS.md

This repository is for an online AI-assisted knowledge base with multimodal ingestion, structured extraction, timeline views, entity indexes, and stylized story rendering.

## Execution Rules

- Work directly unless the task is ambiguous or risky.
- Keep architecture aligned with the docs in `/docs`.
- Preserve the separation between raw assets, derived content, knowledge records, and stylized views.
- Avoid introducing new infrastructure or dependencies unless clearly justified.
- Prefer small, reviewable, reversible changes.
- Verify behavior before declaring work complete.
- Keep progress and design docs synchronized with implementation status.

## Repository Structure

- `web/`: Next.js frontend
- `server/`: FastAPI application, Celery tasks, models, migrations, tests
- `deploy/`: Dockerfiles, compose files, env examples, nginx config
- `docs/`: architecture, API, database, extraction format, deployment, migration, phase planning, and documentation workflow documents

## Backend Rules

- Use FastAPI for HTTP APIs.
- Use SQLAlchemy 2.x models and Alembic for schema changes.
- Use Celery with RabbitMQ for async processing.
- Use Redis only for cache and task-support concerns.
- Use MinIO for raw object storage.
- Version all public APIs under `/api/v1`.

## Migration Rules

- Every schema change must include an Alembic migration file.
- Do not use ORM auto-create in shared or production environments.
- Review autogenerated migration scripts before committing them.
- Keep migrations deterministic and, when practical, reversible.
- Add indexes and constraints through migrations, never by manual database edits.

## Data Model Rules

- Raw source material must remain independently accessible.
- OCR, transcript, frame-caption, and normalized text belong in derivative storage, not in raw asset records unless they are the original text.
- Structured entities, events, relations, timeline items, and embeddings must remain queryable independently of stylized story views.
- Stylized outputs are derived views and must never overwrite canonical knowledge text.

## API Rules

- Keep upload and processing separate.
- Async AI work should be represented by tracked jobs.
- List endpoints should be paginated.
- Responses should follow a consistent envelope shape.
- Core write endpoints should use explicit Pydantic request models instead of generic `dict` payloads.
- Read-heavy route handlers should delegate composition to dedicated query services when possible.

## Deployment Rules

- Docker Compose is the default deployment path for local and first production releases.
- Treat database migration as an explicit deployment step before app startup.
- Keep container configuration environment-driven.
- Persist PostgreSQL, RabbitMQ, Redis, and MinIO data with volumes.

## Documentation Maintenance Rules

- Update `docs/development-phases.md` manually when a phase starts, blocks, or completes.
- When a phase completes, also update the related domain docs listed in that phase.
- Update `README.md` if the developer workflow, stack, or startup instructions changed.
- Update `AGENTS.md` if repository execution rules changed.
- Keep `docs/ai-extraction-format.md` aligned with actual extraction payloads.

## Verification Rules

- For backend changes, run relevant tests plus migration checks when schema changes are involved.
- For API changes, verify request and response shapes.
- For deployment changes, validate compose files and service dependency order.
- For end-to-end changes, rerun `python3 server/scripts/e2e_api_flow.py --phase full`.
- If something was not verified, say so explicitly.
