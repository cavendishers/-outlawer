# Visual Tokens

## 设计目标

这套视觉系统遵循一个原则：颜色不是装饰，而是内容分层工具。单个页面里应先建立 `paper/white` 的稳定阅读面，再用少量强调色告诉用户“哪里是主操作、哪里是信息、哪里是叙事、哪里是时间”。

## 核心颜色职责

| Token | 颜色建议 | 职责 |
| --- | --- | --- |
| `paper` | `#f7f0e6` | 默认内容面、主阅读区、列表主卡片 |
| `bone` | `#fff8ea` | 深层页面 Hero、长阅读面、安静内容卡 |
| `white/canvas` | `#fffdf8` | 输入框、标签、内嵌卡片、图谱画布底层 |
| `muted` | `#4f493f` | 正文说明、弱元数据、辅助提示 |
| `ink` | `#0b0b0b` | 文本、边框、阴影、分隔线 |
| `neon` | `#d8ff19` | 全局导航、主 CTA、单页唯一的强强调块 |
| `aqua` | `#80d6ef` | 信息说明、元数据、系统提示、分析摘要 |
| `peach` | `#ffc3a5` | 叙事正文、关系解读、故事感内容 |
| `gold` | `#f4d35e` | 时间锚点、阶段节点、里程碑、时间线重点 |
| `mint` | `#b8e7c8` | 成功、完成、已处理、健康状态 |
| `ember` | `#f17c67` | 风险、错误、失败、待复核状态 |

## 使用规则

1. 一个页面默认只允许一个 `neon` 主强调块。
2. 深层页面 Hero 优先使用 `bone/quiet`，首页入口和主 CTA 才可以保持高强度。
3. `aqua` 和 `peach` 只在职责明确时出现，不在同一组同层级卡片里来回交替。
4. 时间相关信息优先使用 `gold`，不要和主 CTA 抢焦点。
5. 图谱视图允许用颜色区分节点类型，但必须固定映射，不允许随机交替。
6. 正文说明优先使用 `muted + font-semibold`，`font-black` 只保留给标题、短标签、数字指标和按钮。
7. 列表卡片优先使用 `dossier-card`，通过左侧身份条、标题、摘要和 chips 分层，不靠随机换色制造层次。
8. 图谱画布统一使用 `graph-canvas`，节点统一使用 `graph-node`，移动端必须提供纵向列表替代画布。
9. 列表页必须先决定“内容主角”。如果列表项是主角，Hero 只能做短任务条，统计信息降级为 stamp，不能使用大面积彩色统计卡抢戏。
10. Neo-brutalist 的强视觉只用于拉开层级，不用于平均装饰。每屏最多一个大标题、一个主 CTA、一组主内容卡。
11. 大字号不是 neo-brutalist 的硬性规范。列表页标题应保持强识别但不过度海报化，避免挤压内容。
12. 英文标签只在有产品语义时保留。无意义的风格化英文应改为中文任务标签，避免增加阅读噪音。
13. 中文工作页标题不强制使用 display 英文字体。如果 display 字体让中文笔画变弱，应使用正文中文粗体并通过字距、边框和布局建立 brutal 感。
14. 工作型列表页优先信息密度。顶部区域不能占用过多首屏，操作入口应做成工具条，除非该操作是当前页面唯一主任务。
15. 百分比、评分、置信度必须说明含义。未解释的裸数字不能作为视觉焦点，只能降级为辅助标签。
16. 首页承担品牌入口职责，可以保留高强度海报感；教程、路径分流和工作流解释迁移到 `/guide`，避免首页变成说明书。
17. 详情页首屏必须回答三个问题：这是什么、现在可信到什么程度、下一步该去哪。校对、图谱、来源是默认的三类下一步。
18. 故事视图以阅读为主，标准摘要、原文和 JSON 等调试信息默认降级或折叠，避免和叙事正文争夺注意力。

## 当前项目映射

- 顶部导航和主操作按钮使用 `neon`
- 人物、事件、笔记主内容区使用 `bone/quiet`
- 输入、chips、图谱内嵌卡使用 `canvas`
- 中二风文本、关系视图使用 `peach`
- 摘要、统计、来源信息使用 `aqua`
- 时间线锚点和时间标签使用 `gold`
- 错误反馈和失败状态使用 `ember`

## 组件职责

| Class / Component | 用途 | 注意事项 |
| --- | --- | --- |
| `Panel tone="quiet"` | 深层页面默认容器、Hero、阅读区 | 优先用于需要阅读的页面，避免所有区块都过度强调 |
| `Panel intensity="quiet"` | 次级卡片、指标卡、工作台区块 | 用 `shadow-brutalSoft` 降低视觉噪声 |
| `page-kicker` | 页面顶部英文或功能标签 | 只放短文本 |
| `page-title` | 页面主标题 | 每页只放一个主要标题 |
| `page-lede` | 页面说明文本 | 用于解释当前页面任务，避免 `font-black` |
| `section-kicker` | 区块标签、表单标签 | 适合短标签，不适合正文 |
| `body-copy` | 摘要、说明、长文本 | 统一低饱和正文色 |
| `dossier-card` | 人物、事件、档案列表卡 | 保持干净粗边框，不再内置左侧黑条，避免和硬阴影叠成脏边 |
| `metric-card` | 统计数字卡 | 不默认使用 `neon`，除非是当前唯一焦点 |
| `graph-canvas` | 图谱/时间线画布容器 | 移动端必须有非画布替代展示 |
| `graph-node` | 图谱节点、关系节点 | 节点色固定：人物 `aqua`，事件 `peach/time`，当前焦点可用 `gold/neon` |
| `workbench-header` | 工作型页面顶部标题区 | 高度紧凑，只承载标题、数量 stamp、少量工具入口 |
| `workbench-title` | 工作型页面中文标题 | 使用中文稳定粗体，不使用 display 英文字体 |
| `workbench-stamp` | 数量、状态、当前过滤结果 | 小尺寸标签，不作为大统计卡抢主内容 |
| `tool-action` | 工具条按钮 | 小按钮，仅用于导入、图谱、重置等辅助动作 |
| `dense-record` | 高密度记录行 | 列表页主内容卡，优先一行摘要和少量 chips |
| `workbench-header` + `workbench-stamp` | 审核、运维、图谱工作台等操作页顶部 | 只展示当前任务、关键数量和少量工具按钮，不再使用大 Hero + 大数字卡 |

## 样板页原则

`/events` 是当前列表页样板：

- Hero 使用短任务条，不再承担大海报职责。
- 事件数量用 `stamp` 放在标题附近，不再使用大统计卡。
- 事件卡是页面主角，桌面端采用紧凑的 `time + content` 双栏记录行。
- 时间使用 `gold`，摘要限制一行，置信度必须带“置信度”标签。
- 页面说明只回答当前任务，不写长介绍。
- 标题字号克制在工作页尺度，不使用首页级超大海报字体。
- 无信息价值的英文装饰标签改成中文。
- 中文主标题使用稳定粗体，卡片标题必须低一档，避免主标题比列表项还弱。
- 操作入口使用小型工具按钮，避免和事件记录争夺注意力。

已迁移页面：

- `/events`
- `/library`
- `/people`
- `/timeline` 的顶部和时间线列表
- `/search` 的顶部和优先命中列表
- `/review` 的审核队列顶部和筛选区
- `/operations` 的运维后台顶部、指标和操作入口
- `/graph` 工作台顶部和空状态
- `/inbox`、`/tools`、`/login`、错误页和 404 页面
- `/notes/[id]` 的卷宗详情、AI 分析闭环和抽取运行区域

## 后台 / 操作页原则

- 审核、运维、图谱工作台属于工作型页面，不使用首页级大标题、装饰英文或大面积指标 Hero。
- 首屏必须优先暴露“现在要处理什么”，数量信息放入 `stamp`，不要让统计卡抢走列表和操作区的注意力。
- 工具入口使用 `tool-action`，颜色默认 `canvas`，只有真正主行动作才允许使用 `neon`。
- 指标卡可以保留，但字号降级，作为状态概览而不是视觉主角。
- 技术调试区域可以保留 JSON、payload 等概念，但页面可见标签优先中文化。
- 导入、登录、工具台、错误页属于入口型工作页，也使用 `workbench-header`，避免回到大海报式欢迎页。
- 卷宗详情页的 AI 分析区域要优先解释“当前生效版本、模型、状态、结构化数量、人工动作”，JSON 只能作为折叠调试入口。

## 后续扩展建议

- 如果以后要补“审核 / 风险分级”模块，可以让 `ember` 和更深一档的红棕色组成风险梯度。
- 如果以后要补“任务完成 / 导入完成”状态，可以用 `mint` 作为统一成功色，不再复用 `neon`。
- 如果未来有更复杂的数据可视化，优先扩展明度层级，再扩展新色相，避免再次回到多色混用。

## 导航规则

- 顶部主导航只平铺最高频任务：`首页`、`导入`、`搜索`。
- 知识库浏览入口收进 `知识库` 菜单：`档案`、`人物`、`事件`、`图谱`。
- 后台和低频工作入口收进 `更多` 菜单：`教程`、`审核`、`运维`、`工作台`。
- 当前路由属于菜单内部时，菜单触发器本身高亮，减少导航栏横向拥挤。

## 信息架构规则

- 首页：负责品牌第一印象和少量核心入口，不承载长教程。
- 教程页 `/guide`：负责路径分流、处理流程和产品原则解释，主入口固定为 `导入`、`搜索`、`图谱工作台`。
- 列表页：负责筛选、定位、对比，不承载长解释；记录项是视觉主角。
- 详情页：负责结论、证据摘要和下一步动作；校对入口必须在首屏可见。
- 故事页：负责阅读和表达；标准视图、原文、调试内容必须降级。
- 审核 / 运维页：负责待办和风险，不做品牌表达。
