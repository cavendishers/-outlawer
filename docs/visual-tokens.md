# Visual Tokens

## 设计目标

这套视觉系统遵循一个原则：颜色不是装饰，而是内容分层工具。单个页面里应先建立 `paper/white` 的稳定阅读面，再用少量强调色告诉用户“哪里是主操作、哪里是信息、哪里是叙事、哪里是时间”。

## 核心颜色职责

| Token | 颜色建议 | 职责 |
| --- | --- | --- |
| `paper` | `#f7f0e6` | 默认内容面、主阅读区、列表主卡片 |
| `bone` | `#fff8ea` | 深层页面 Hero、长阅读面、安静内容卡 |
| `white/canvas` | `#fffdf8` | 输入框、标签、内嵌卡片、图谱画布底层 |
| `muted` | `#6f675c` | 正文说明、弱元数据、辅助提示 |
| `ink` | `#0b0b0b` | 文本、边框、阴影、分隔线 |
| `neon` | `#d8ff19` | 全局导航、主 CTA、单页唯一的强强调块 |
| `aqua` | `#80d6ef` | 信息说明、元数据、系统提示、分析摘要 |
| `peach` | `#ffc3a5` | 叙事正文、关系解读、故事感内容 |
| `gold` | `#f4d35e` | 时间锚点、阶段节点、里程碑、时间线重点 |
| `mint` | `#b8e7c8` | 成功、完成、已处理、健康状态 |
| `ember` | `#f17c67` | 风险、错误、失败、待复核状态 |

## 使用规则

1. 一个页面默认只允许一个 `neon` 主强调块。
2. 深层页面 Hero 优先使用 `bone/quiet`，首页入口和主 CTA 才可以保持高强度。
3. `aqua` 和 `peach` 只在职责明确时出现，不在同一组同层级卡片里来回交替。
4. 时间相关信息优先使用 `gold`，不要和主 CTA 抢焦点。
5. 图谱视图允许用颜色区分节点类型，但必须固定映射，不允许随机交替。
6. 正文说明优先使用 `muted + font-semibold`，`font-black` 只保留给标题、短标签、数字指标和按钮。
7. 列表卡片优先使用 `dossier-card`，通过左侧身份条、标题、摘要和 chips 分层，不靠随机换色制造层次。
8. 图谱画布统一使用 `graph-canvas`，节点统一使用 `graph-node`，移动端必须提供纵向列表替代画布。

## 当前项目映射

- 顶部导航和主操作按钮使用 `neon`
- 人物、事件、笔记主内容区使用 `bone/quiet`
- 输入、chips、图谱内嵌卡使用 `canvas`
- 中二风文本、关系视图使用 `peach`
- 摘要、统计、来源信息使用 `aqua`
- 时间线锚点和时间标签使用 `gold`
- 错误反馈和失败状态使用 `ember`

## 组件职责

| Class / Component | 用途 | 注意事项 |
| --- | --- | --- |
| `Panel tone="quiet"` | 深层页面默认容器、Hero、阅读区 | 优先用于需要阅读的页面，避免所有区块都过度强调 |
| `Panel intensity="quiet"` | 次级卡片、指标卡、工作台区块 | 用 `shadow-brutalSoft` 降低视觉噪声 |
| `page-kicker` | 页面顶部英文或功能标签 | 只放短文本 |
| `page-title` | 页面主标题 | 每页只放一个主要标题 |
| `page-lede` | 页面说明文本 | 用于解释当前页面任务，避免 `font-black` |
| `section-kicker` | 区块标签、表单标签 | 适合短标签，不适合正文 |
| `body-copy` | 摘要、说明、长文本 | 统一低饱和正文色 |
| `dossier-card` | 人物、事件、档案列表卡 | 内部使用 `dossier-card-content` 避开左侧黑条 |
| `metric-card` | 统计数字卡 | 不默认使用 `neon`，除非是当前唯一焦点 |
| `graph-canvas` | 图谱/时间线画布容器 | 移动端必须有非画布替代展示 |
| `graph-node` | 图谱节点、关系节点 | 节点色固定：人物 `aqua`，事件 `peach/time`，当前焦点可用 `gold/neon` |

## 后续扩展建议

- 如果以后要补“审核 / 风险分级”模块，可以让 `ember` 和更深一档的红棕色组成风险梯度。
- 如果以后要补“任务完成 / 导入完成”状态，可以用 `mint` 作为统一成功色，不再复用 `neon`。
- 如果未来有更复杂的数据可视化，优先扩展明度层级，再扩展新色相，避免再次回到多色混用。
